- Five cropped visual anchors from real 1280×720 runtime frames identify the “Thanks for playing / Open Now!” modal (title plus either normal or hover button) and the main-menu Browse/Host labels. The detector returns the matched bounding box, and the policy derives the click center from that box. - The behavior policy requires two stable observations, a verified calibration, verified assets, and at least 0.94 reward confidence. It can propose only `CLICK_REWARD_OPEN`; the ACTIVE executor independently rejects every other gameplay action. Input execution returns only `PENDING_VERIFICATION`; success is reported only after two consecutive valid `REWARD_RESULT` or `MAIN_MENU` observations. It waits 12 seconds for a visual change, permits at most one retry while the same verified modal remains, and then requests intervention. UNKNOWN never proposes input and pauses ACTIVE after 20 seconds.
- OBSERVE constructs no live input controller or executor thread. REPLAY uses its existing input-free sink. DISABLED releases capture, recorder, input, and policy resources. Each policy decision includes observation, screen state/confidence, action, reason, result, next state, and timestamp in bounded in-memory diagnostics and structured logs.

## Farm-world recommendation and current limits

Use one private, stable online world configured manually for a safe idle character and a nearby Science Machine **if the observed gift-claim flow requires one**. Keep the camera and UI scale fixed at the calibrated 1280×720 profile. This is preferable to navigation or survival AI for a playtime-drop worker. The implementation does not use a drop timer or assume a Klei drop interval.

The screen enum reserves MAIN_MENU, REWARD_RESULT, IN_WORLD_IDLE, GIFT_AVAILABLE, LOADING, DISCONNECTED, PAUSED, DEAD, CHARACTER_SELECTION, and UNEXPECTED_MODAL. `LOGIN_REWARD_AVAILABLE` and `MAIN_MENU` now have real-frame classifications and an offline-replayed transition. A distinct reward-result modal was not observed; the manual click returned directly to the main menu. Farm-world entry, gift detection/claiming, disconnect recovery, reward-result dismissal, and sustained online idle are **not yet automated**. The executor whitelist remains only `CLICK_REWARD_OPEN`; no combat, movement, exploration, or generic UI click is enabled. Although still present in the whitelist, this action cannot be counted implemented until a future supervised GameWorker click is followed by the verified screen transition.

The service’s existing worker remains `DISABLED`; Steam/Xvfb/game were not restarted. The supervised script used explicit calibration verification for the already validated 1280×720 runtime. The control-plane worker has not been switched to ACTIVE. If the reward flow appears again naturally, the code can recognize and await the transition, but end-to-end action verification remains outstanding until an explicitly supervised GameWorker click is observed to change the screen.
